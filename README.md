# Voltaris: готовая папка бэкенда для Render Free

Обновление с регистрацией и подписками описано в [README-ACCOUNTS.md](README-ACCOUNTS.md).

В GitHub загружай содержимое только этой папки (deploy/render), а не весь antileak. Здесь нет приватных ключей или seed. Папку deploy-private никуда публично не загружай.

## Развёртывание

1. Создай репозиторий GitHub и загрузи в его корень файлы из этой папки: Dockerfile, voltaris-auth-service.jar, render.yaml, README.md и файлы с точкой.
2. В Render выбери New → Blueprint, подключи этот репозиторий. В render.yaml указан тариф free. Альтернатива: New → Web Service → этот репозиторий → Docker → Free, health check /healthz.
3. Для секрета VOLTARIS_AUTH_STATE_B64 вставь содержимое локального файла deploy-private/render/server-state.b64. Это секрет сервера; не добавляй его в репозиторий, Dockerfile, чат, публичный архив или клиентский лаунчер. На Render его можно добавить в Environment. Альтернатива для другого Docker-хостинга: секретный файл и переменная VOLTARIS_STATE_FILE с путём к нему.
4. После успешного Deploy открой https://ИМЯ-СЕРВИСА.onrender.com/healthz. Ответ должен быть ok. Тот же тест: powershell -File check-host.ps1 -Url https://ИМЯ-СЕРВИСА.onrender.com/
5. Адрес авторизации: https://ИМЯ-СЕРВИСА.onrender.com/v1/authorize . У адреса нет административного интерфейса.

## Что ещё требуется для клиентов

Само размещение сервера НЕ переключает уже скачанный JAR на этот сервер. Нынешний релиз содержит подписанный адрес http://127.0.0.1:48721/v1/authorize. Когда получишь реальный HTTPS-домен, необходимо подключить его в клиентской поставке/лаунчере и проверить запуск. Текущий лаунчер на другом ПК пока не заработает автоматически только от загрузки этой папки. Редактировать подписанные метаданные вручную нельзя.

Отдельный тестовый клиентский токен находится только в deploy-private/render/client-*.token. Он выдан на 720 часов по умолчанию. Пользователю нужен его отдельный токен, а не серверный server-state.b64. Токен не вшит в публичный пакет и сам по себе не настраивает текущий лаунчер на удалённый сервер.

## Состояние и бесплатный тариф

У Render Free временная файловая система: новый сервер восстанавливает ключи, зарегистрированный релиз и записи токенов из секрета при каждом старте. Ключи не генерируются заново. Контейнер работает от непривилегированного пользователя. JAR Voltaris сервер не раздаёт: он остаётся на Google Диске; этот сервис выдаёт только подписанное разрешение после проверки токена.

Выдача/отзыв токенов остаются локальными CLI-командами владельца. После изменения .auth снова экспортируй состояние скриптом prepare-backend-hosting.ps1, обнови секрет в Render и перезапусти сервис. Изменения в эфемерной папке контейнера после рестарта не сохранятся.

Render Free засыпает после 15 минут без запросов; пробуждение может занимать около минуты. Перед запуском клиента дождись ok на /healthz либо выполни check-host.ps1. Текущий клиент может не дождаться холодного старта — его интеграцию с удалённым хостом ещё нужно настроить после получения домена. Free — вариант для тестирования, не гарантия постоянной доступности. Дополнительные услуги и выход за лимиты тарифицируются по правилам платформы.

## Другие варианты

Koyeb Free: один небольшой инстанс 512 MB RAM, 0.1 vCPU, 2 GB SSD; засыпает после часа без запросов. Этот Dockerfile совместим с подобным контейнерным запуском: PORT=10000, секрет состояния и health check /healthz.
Google Cloud Run: есть бесплатная квота, но это тариф с биллингом за превышение, а не безусловно бесплатный VPS.

## Проверки

Java-бэкенд проверен локально: экспорт/восстановление состояния, health check, отказ без токена и по неверному токену, подписанное разрешение по действующему токену, отсутствие доступа к файлам ключей через HTTP и отказ при ZIP traversal. Docker-образ и облачное развёртывание здесь не запускались.


## Панель Voltaris Control

Для действующего сервиса kaltaris обнови Dockerfile и voltaris-auth-service.jar в корне его GitHub-репозитория. В Render → Environment добавь VOLTARIS_ADMIN_PUBLIC_KEY. Значение лежит в локальном deploy-private/operator/admin-public-key.txt. Существующее состояние авторизации VOLTARIS_AUTH_STATE_B64 нужно сохранить. После развёртывания открой /admin.

На странице нажми «Получить код», скопируй его и запусти в PowerShell из папки проекта:

    .\operator.ps1

Вставь одноразовый код в PowerShell. Полученную подпись вставь в браузер. Код действует 3 минуты и используется один раз, сеанс действует 1 час. Закрытый operator.key остаётся на ПК. Для нового ключа на локальной машине используется .\operator.ps1 init.

На каждом клиентском ПК нужно заменить EXE и включить передачу статуса в настройках лаунчера. С действующим пользовательским токеном лаунчер отправляет ник и статус собственной игры, а также категории обнаружения архивов и неизвестных папок и названия совпавших инструментов. Имена файлов, заголовки окон и список процессов целиком в эти события не входят. Срабатывания внутри подписанного JAR остаются на прежнем канале. Наблюдение — клиентские сигналы, поэтому оно не гарантирует полноту и не подтверждает попытку взлома.

Панель хранит до 1000 последних срабатываний в памяти сервера. После перезапуска Render история исчезает. Сессии без сигнала исчезают из активных примерно через 65 секунд. При недоступности сервера отправка выполняется по возможности без очереди на диске.
