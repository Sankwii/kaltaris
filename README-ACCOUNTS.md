# Аккаунты Voltaris на Render

Обновление добавляет регистрацию в лаунчере, управление подпиской через /admin и привязку аккаунта к одной установке Windows. Игровой ник и логин аккаунта задаются отдельно. Аккаунт создаётся без подписки. Администратор выдаёт дни, отзывает доступ или сбрасывает привязку. После сброса устройство привязывается при следующем успешном входе.

## Установка на действующий kaltaris.onrender.com

1. Создай базу PostgreSQL. Например, Neon Free. В Neon → Connect выбери Pooled connection и возьми хост, имя базы, пользователя и пароль. Ссылка на документацию внизу.
2. Замени в GitHub файлы Dockerfile, .dockerignore, voltaris-auth-service.jar и добавь postgresql.jar из этого архива. Все четыре файла должны находиться в корне. Инструкции из архива можно обновить вместе с ними.
3. В Render → Environment укажи все четыре переменные в одном изменении. Сохрани существующие VOLTARIS_AUTH_STATE_B64 и VOLTARIS_ADMIN_PUBLIC_KEY.

| Переменная | Что указать |
|---|---|
| VOLTARIS_DB_URL | jdbc:postgresql://HOST/DB. Например jdbc:postgresql://ep-example-pooler.us-east-1.aws.neon.tech/neondb. Без логина, пароля и параметров запроса |
| VOLTARIS_DB_USER | Имя роли из PostgreSQL |
| VOLTARIS_DB_PASSWORD | Пароль роли из PostgreSQL |
| VOLTARIS_ACCOUNT_RELEASE | 5920ab246e629b15e14a4659dad6ec9700c0ec353fd9f0aad4fd95e27ec13a89 |

4. Выбери Save, rebuild, and deploy. Дождись Live. Backend создаст таблицу voltaris_accounts при запуске. Используй роль PostgreSQL с правом создать таблицу в выбранной базе.
5. Распакуй новый клиентский ZIP. В настройках Voltaris введи логин и пароль из 12–96 символов, затем нажми «Создать аккаунт». В /admin в разделе «Пользователи и подписки» выдай этому логину дни. Введи пароль повторно и нажми «Запустить Minecraft».

Старый подписанный JAR и его адрес скачивания остаются прежними. Новый лаунчер получает временную сессию по HTTPS и передаёт её игровому процессу через канал Windows в памяти. У пользователя нет файла voltaris.token. Когда в Render включён режим аккаунтов, прежние ручные токены отклоняются, поэтому игрокам потребуется обновлённый EXE и аккаунт. Переводить действующий сервис лучше после подготовки базы и нового архива клиента.

## Проверки доступа

Пароли хранятся в виде PBKDF2-HMAC-SHA256 с отдельной случайной солью. Сервер хранит SHA-256 от идентификатора установки Windows с пространством имён Voltaris. Это привязка по отпечатку установки, который можно подделать при контроле над ПК. Сброс устройства доступен из админки. Ручное восстановление пароля и автоматическая оплата в эту версию не входят.

При запуске сервер проверяет сессию, срок подписки и привязку, а затем подписывает одноразовый ответ Ed25519 для существующего релиза. Клиент проверяет сертификат HTTPS, подпись, запрос и хеш данных релиза. Подмена адреса через hosts или DNS не выдаёт действительную подпись. Отзыв блокирует новые запросы на запуск. Уже работающая JVM автоматически не завершается. Временная сессия действует до четырёх часов и сбрасывается при перезапуске бэкенда. Аккаунты и подписки остаются в PostgreSQL.

Проверены регистрация, запрет без подписки, несовпадение устройства, отказ по старому токену, подпись ответа, сброс устройства, отзыв и сохранение состояния после повторного открытия базы. Интеграционные тесты выполнены на локальной SQL-базе в режиме совместимости с PostgreSQL. Облачный PostgreSQL и аккаунтный запуск через Render требуют настройки выше.
